## Context

离线控制台把基础运行状态、固定 API-503 Case 时间线和 12 项 Replay 评测证据放在同一个 Vue 页面中。页面只读且对每个从 API 获得的快照执行完整校验；现有中文项目说明与英文可见文案不一致。

## Goals / Non-Goals

**Goals:**

- 将所有面向操作者的静态和派生展示文本统一为简体中文。
- 保留证据 ID、哈希、API 路径、契约字段、状态枚举与 reason code 的原始稳定值。
- 以现有的纯渲染模型测试和生产构建验证本地化不改变离线、只读与无副作用边界。

**Non-Goals:**

- 不引入可切换的多语言框架、运行时语言协商或翻译服务。
- 不修改 API、JSON Schema、存储、报告内容或任一工作流/策略能力。
- 不翻译机器可读标识，或将 fixture-local 记录描述为真实投递、客户签收或问题解决。

## Decisions

### 在展示层翻译，而非翻译证据或协议值

在 `App.vue`、`foundation-status.ts`、`evaluation-report.ts` 和
`operator-case.ts` 中替换操作者可见标签与说明。证据对象继续使用原始字段和
枚举值，详情中的 ID、哈希和 reason code 原样显示。

这使本地化不会改变哈希输入、后端契约或可复验报告。将翻译写入 API 或报告会
扩大兼容性与证据重建风险，故不采用。

### 保持安全边界的明确中文措辞

将 `offline`、`Replay-only`、`fixture-local`、未支持指标和不可用状态翻译为
明确的中文语义，同时保留括号中的原始技术标识（如 `fixture-local`）。不以
“已送达”“已解决”等中文措辞替代受限能力。

### 以现有渲染模型测试作为回归边界

现有前端单元测试覆盖就绪及不可用渲染状态。更新预期文案，并补充代表性的中文
断言，随后运行 Web Console 测试、生产构建和离线控制台验收；无需启动模型、
网络或外部写入。

## Risks / Trade-offs

- [遗漏动态派生文案] → 检索 `apps/web-console/src` 中全部用户可见字符串，并让测试覆盖三类渲染模型。
- [翻译弱化安全含义] → 在 fixture-local、不可用指标和安全状态处保留明确的限制性表述，并复用已有行为断言。
- [机器标识被误翻译] → 仅转换标签；ID、哈希、枚举和原因码按原始值展示。
